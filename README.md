# Saltline · 自由混战

基于原版 Saltline 港口 FPS 改造的浏览器多人游戏，保留原地图、枪械动画、程序化材质、雨景和音效。

## 启动

需要 Node.js 22.13 或更新版本（使用内置 SQLite）；推荐 Node.js 24 LTS。在本目录运行：

```sh
npm ci
npm start
```

也可以在 macOS 双击 `启动游戏.command`。默认地址 http://localhost:18453 。服务器使用 `0.0.0.0` 监听，可用 `PORT=8080 npm start` 更换端口。

1. 输入呼号，点击“创建房间”。
2. 朋友打开同一台服务器的地址，输入 6 位房间码加入。
3. 至少 2 人，由房主开始；最多 8 人。
4. 每局 5 分钟，击杀最多者获胜，同分并列。死亡后 3 秒复活，复活保护 2 秒，开枪立即解除保护。
5. 本局结束后由房主“再来一局”。

操作：WASD 移动，鼠标瞄准，左键开火，右键开镜，R 换弹，Space 跳跃，Shift 冲刺，C 蹲下，Tab 战绩。Esc 释放鼠标，比赛仍继续。浏览器无法锁定鼠标时保留原版拖动/鼠标移动瞄准方式。大厅可调整画质。备用弹药无限，每匣 30 发，伤害 26，保留原版后坐力与散布。

## 两台电脑怎样连接

同一局域网中，朋友使用服务器电脑的局域网 IP，例如 `http://服务器IP:18453`，而不是自己的 localhost。需要网络允许访问该端口。复制邀请链接时，地址栏应当已使用朋友可访问的服务器地址。

公网游玩需要一台能够持续运行 Node.js 的主机，并通过 HTTPS 反向代理同时转发网页与 `/ws` 的 WebSocket 升级请求。这个项目不能只上传静态 HTML 就实现联机。当前没有部署到公网，也未验证跨公网网络条件。

服务器重启会清空房间和战绩。普通断线保留玩家 45 秒，名单显示“掉线中”，房主身份保留；本标签页自动按约 0.5、1、2、4、8 秒退避重连，刷新也会使用 sessionStorage 中的恢复凭证。恢复后沿用原 id、战绩和角色外观，继续大厅、角色准备、对局或结算；重连期间暂停操作并保留最后画面。角色仍留在战场，可受伤或复活。超时离房，主动“退出”或结算“返回大厅”立即离房并清除凭证。新玩家不能加入角色准备中或进行中的对局。同一凭证恢复会顶替旧连接；不要分享恢复凭证。没有账号、持久化排行、匹配队列、聊天或观战系统。

### HTTPS 部署示例

本地默认继续使用 `http://localhost:18453`，无需证书。公网先将域名 DNS 指向主机、放通 80/443，参考 `deploy/Caddyfile` 与 `deploy/compose.yml`：

```sh
cp .env.example .env
# 编辑 .env 配置管理员及所需接口；证书和私钥均留在仓库外
export DOMAIN=你的公网域名
docker compose -f deploy/compose.yml up -d
```

此命令仅供自行部署参考，本批未执行部署。Caddy 自动申请证书，反代网页和 `/ws`（自动支持升级）；Node 服务只在容器网络暴露 18453，不映射公网端口。数据保存于命名卷。代理后使用 `TRUST_PROXY=1`，仅信任会覆盖 `X-Forwarded-For` 和 `X-Forwarded-Proto` 的自有代理，并阻止绕过代理访问 Node。邀请时从 `https://` 地址复制链接，客户端自动使用 `wss://`。Let’s Encrypt 不能为纯 IP 签发证书；没有域名先继续本地 HTTP，不要强行部署公网 HTTPS。

也可以直接设置 `TLS_CERT`、`TLS_KEY` 为仓库外的 PEM 文件路径（必须同时设置），Node 会创建 HTTPS 服务；`PORT` 仍默认 18453。程序调用支持 `createGameServer({tls:{cert,key}})`，接受字符串或 Buffer。管理员 Cookie 在真实 TLS 或 `TRUST_PROXY=1` 且 `X-Forwarded-Proto=https` 时自动带 Secure，本地 HTTP 不需要更改配置。`HSTS=1` 可在这些 HTTPS 响应上启用一天的 HSTS，HTTP 响应不会携带；默认关闭。自签名证书仅供本机测试，不代替公网可信证书。

## 实现与验证

- `public/index.html`：原版程序化场景和渲染代码，仅改造引导入口；固定地图种子 4207。
- `public/client.js`、`public/pvp.css`：房间 UI、联机适配、远端角色、预测与位置校正。
- `server/match.js`：服务器对局规则、弹药、命中、计分和复活。
- `server/physics.js`、`server/map.json`：服务器移动与碰撞，557 个原版碰撞盒和 38 个候选出生点。
- `server/index.js`：可选 HTTPS、WebSocket、房间隔离、心跳、断线恢复与消息限流。
- `tests/`：规则及真实双 WebSocket 集成测试；`tests/browser-fixture.js` 仅用于受控浏览器验收，不由 `npm start` 启动。
- `docs/verification.md`：实测范围和截图；`docs/verification-net.md`：本次 HTTPS、断线恢复和延迟补偿验收。

```sh
npm test
```

服务器根据玩家输入计算移动、重力和碰撞，客户端预测操作，远端插值。服务器计算射线命中与遮挡，客户端不能上报伤害或目标。服务端保留约 300ms 位置与蹲姿历史，客户端依据 pong 的服务器时间与 RTT 估算射击时间，命中检测最多回溯 250ms，包含射击者和目标；伤害、射速、弹药与当前复活保护仍由服务器判定。不带 shotTime 的射击保持原有当前时刻检测。跨复活不回放上一条生命；静态墙体不回溯。中等本地误差平滑校正，大于 1.2 米再对齐；远端用速度最多外推 100ms / 0.6 米。尚无竞技级反作弊，高延迟与跨公网体验仍需实网调优。远端人物是新增的程序化简化模型。

原始游戏来源：https://pages.eiaserinnys.me/d/saltline-fable52 。下载原件保留在本项目上级的 `saltline-fable52.html`。字体仍使用原页面的 Google Fonts；字体网络不可用时使用系统字体。

## 文字自定义角色

大厅点击“自定义角色”；对局中可点击“角色外观”查看，生成和换装默认仅限大厅，可由管理员开启：输入 2—300 字描述 → 生成三维预览 → 拖动查看 → 点击“装备这个角色”。其他玩家随后看到同一个外观；可随时使用默认外观。每局每位玩家最多成功生成一次（大厅准备与对局共用），失败可重试，默认外观不占次数，再来一局后重置；后台测试不受此限。最近 5 个生成结果及装备选择保存在当前浏览器，下次刷新可恢复。没有图片上传入口。

AI 返回受限的几何结构数据，程序生成曲线触手、装甲、毛发、鳞片等细节；渲染器没有针对物种的预设。生成结果仍可能与描述有偏差，需玩家预览确认。当前自定义角色支持整体移动、朝向与蹲下缩放，尚未实现任意肢体的独立行走和持枪动画。角色统一归一到 1.8 米高；外形宽度可以不同，但服务器命中、移速和伤害仍沿用统一规则。

启动 AI 功能（密钥只配置在服务器端）：

```sh
cp .env.example .env
# 编辑 .env 填入密钥与实际支持的模型/接口
node --env-file=.env server/index.js
```

也可由进程管理器注入上述环境变量。不配置密钥时，游戏仍能运行，生成按钮提示未开启；已有资产仍可预览和装备。环境变量方式使用 Responses API；后台自定义接口支持 Responses 或 Chat Completions，可指定接口地址和模型名称，启用前须通过角色生成测试。

生成使用异步任务接口，以下为默认值，可由后台调整：最多 2 个任务同时执行，150 秒超时；每 IP 每小时 6 次，提交间隔至少 15 秒，失败任务也占限额。默认 IP 取直接连接地址；仅在可信代理覆盖 X-Forwarded-For 且端口不允许绕过代理访问时启用 TRUST_PROXY=1，否则代理下玩家共享额度。限额是进程内状态，重启会重置，当前没有账号归属和跨实例配额。

`server/data/avatars/` 保存经过校验的 JSON 资产，部署时应挂载持久目录并备份；不可放入只读文件系统。房间快照只传资产编号，客户端按需获取结构。公开资产编号可供访问及装备，无私有角色权限。恢复默认不会删除资产；当前没有自动清理历史资产的机制。

本次本地验收记录见 `docs/verification-text-avatars.md`。不代表已更新线上服务器。


## 管理后台（v0.2）

访问 `/admin`。后台与游戏共用同一个 Node 进程，包含运行概览、AI 接口、角色设置、生成记录和系统设置。

1. 在 `.env` 设置 `ADMIN_PASSWORD`（至少12个字符）。
2. 在终端运行下面的命令生成加密主密钥，写入 `.env` 的 `ADMIN_ENCRYPTION_KEY`。生成一次并妥善保管，后续重启必须沿用。
3. 使用 `node --env-file=.env server/index.js` 启动，打开 `/admin` 登录。

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

没有默认管理密码；缺少密码或主密钥时，管理接口拒绝访问，游戏仍可启动。首次初始化后，密码以数据库中的哈希为准；修改环境变量不会重置已有密码。后台修改密码会撤销全部管理会话。管理会话8小时过期，重启后需要重新登录。HTTPS 自动启用 Secure；`ADMIN_COOKIE_SECURE=1` 仍可强制启用，本地 HTTP 保持 0，避免浏览器不发送登录 Cookie。不要把管理员密码或主密钥放到前端代码或 Git。

### 接口与开关

- 保存最多10个接口，支持 Responses 和 Chat Completions。默认从已有 `OPENAI_*` 环境配置建立一个接口（仅首次建立数据库时导入）。
- 密钥留空保持，勾选“清除密钥”才移除；API 响应不返回明文。后台输入的新密钥以 AES-256-GCM 加密保存。使用环境变量的接口会继续从环境取值，修改环境需重启。
- 连通性测试读取 `/models`，部分服务可能不支持；角色生成测试实际调用所选模型并消耗额度。新启用/改变地址、协议、模型或密钥的接口，必须先通过角色生成测试，测试不会自动装备。第一版手动切换，不会自动切换备用接口。
- 自定义角色总开关关闭后，在线玩家立即回退默认外观。文字生成、换装、对局内操作和玩家 3D 预览可分别调整。加入后大厅显示房间名册；房主开始后弹出角色选择，开启 120 秒准备窗口，显示倒计时与其他玩家状态。谁先准备好谁先入场：首人入场开始五分钟比赛，后来者单独出生，不重置在场者位置或战绩。选择默认直接入场；关闭预览时生成成功自动装备并入场，开启预览时必须确认装备，未确认不入场。本地保存的角色可从最近生成中选择，不在连接时自动装备、代替用户确认。准备窗口在比赛开始后仍继续，未入场者可继续生成／装备；到期已连接的未入场者取消任务并用默认外观入场，离线者重连后按截止状态处理。全部入场或到期后关闭倒计时。窗口内最多 8 路生成，不受普通 IP 并发、每小时或冷却限制；单次最多 120 秒且不超过窗口剩余时间。已入场者遵循原有本局生成额度和对局内更换策略。开始后禁止新身份加入，允许原身份重连；未入场者不参与战斗。后台预览始终可用，预览开关控制官方客户端展示，角色数据仍供游戏渲染使用。
- 保存后无需重启，公共设置通过 WebSocket 同步；已经运行的任务保留提交时的接口与超时。全局关闭后任务可完成，但无法装备。恢复默认始终允许。
- 配置带版本检查，另一管理员页已保存时，旧页面须重新读取。系统设置可回退历史配置，产生新版本；回退不会改变密码、任务记录或角色禁用状态。

### 数据与备份

`server/data/control.sqlite` 保存配置版本、密码哈希、脱敏操作记录、生成记录和角色禁用状态。SQLite WAL 及 SHM 侧文件也属于运行数据。`server/data/avatars/` 保存角色 JSON。全部不提交 Git。

备份需覆盖数据库、角色文件，并单独保护加密主密钥；可先停服务再复制整个 `server/data/`，避免遗漏 WAL 中尚未合并的数据。丢失主密钥将无法解密已保存的 API Key。角色文件与数据库均需可写且持久化，当前设计为单进程单实例。公网 HTTP 下前端生成临时接口编号不依赖安全上下文的 `crypto.randomUUID`。

记录默认保留30天（后台可设1—365天），启动时、保存配置时及每5分钟清理一次；只删除过期任务与操作记录，角色文件和配置版本不会自动删除。禁用角色后在线玩家回退默认，禁用角色只允许管理员读取预览。已删除/过期记录不会因配置回退恢复。

当前不提供玩家永久账号、付费额度、管理员角色分级、API 自动故障切换、自动费用统计或多实例统一控制。额度仍按进程内 IP 计算，重启会重置。测试结果见 `docs/verification-admin.md`。
