# 优化方案（第一批）：压缩文档截图

## 背景

最新分支 `codex/admin-console` 工作树约 20.4 MB，其中 `docs/` 截图约 18.8 MB（23 张 PNG），游戏代码和运行时资源大约只有 1.6 MB。体积大头是未压缩的验收截图。

## 本次范围

只做仓库体积优化：压缩 `docs/` 下截图，保持文档可读，不改玩法，不改运行时代码。

明确不做（留到后续批次）：

- 域名和 HTTPS
- 断线重连
- 延迟补偿 / 延迟回溯
- 管理后台公网加固
- 重写 git 历史（会让已有克隆全部作废）

说明：本批只提交压缩后的文件，当前检出体积会下降，但 GitHub 上的历史占用不会立刻变小。

## 执行要求

1. 在当前分支 `optimize/compress-docs-screenshots`（基于 `codex/admin-console`）上工作。
2. 压缩所有 `docs/**/*.png`，保持相对路径和文件名不变，Markdown 引用不用改（除非改了扩展名，那就必须同步改完所有引用并删除旧 PNG）。
3. 压缩工具：优先 `pngquant` + `oxipng`（如果已安装）。否则使用本机已安装的 Python Pillow（`from PIL import Image`）将 PNG 以优化过的调色板/压缩参数原地写回，或使用已安装的 `cwebp`（若改成 WebP，必须同步所有引用并删除旧 PNG）。不要缩小像素尺寸。
4. 目标：大于 1 MB 的图压到大约 200-500 KB，且界面文字仍能看清；较小的图按比例压缩。不要压到看不清。建议质量约 70-85。
5. 不要修改 `public/`、`server/`、`tests/` 里的功能代码。不要改 `public/index.html`（里面的较大资源是运行时需要的）。
6. 可在 README 或文档中补充一两句：提交截图前先压缩，不要把未压缩的 1 MB+ PNG 提交进仓库。
7. 运行 `npm test`，必须通过。
8. 写 `docs/optimization-report.md`，列出每张图压缩前后字节数和总计对比。
9. 不要 `git push`，不要 force push，不要改历史。不要提交；只改文件，提交由我来做。
