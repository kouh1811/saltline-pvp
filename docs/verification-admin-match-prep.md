# 后台接口与开局角色准备验证

验证日期：2026-11-12。工作分支：`feature/admin-providers-match-prep`。基线：`50fa0e1365a0f75008bb5c205f1373dc31357cd7`。验证对象为该基线上的未提交工作区。

## 实现范围

- 后台接口编号使用 `crypto.getRandomValues`，不可用时降级到时间、随机数和递增序号；不依赖 HTTP 公网不可用的 `crypto.randomUUID`。空接口列表直接展示新建表单。保留地址、协议、模型、密钥字段及生成测试通过后方能启用的规则。
- 自定义 Responses / Chat Completions 接口启用后，玩家生成使用所保存的地址、模型和密钥；配置、任务及记录不回传密钥。
- 房间上限为 8 人，至少 2 人开局。大厅、人口、规则和 README 文案同步。
- 每位玩家每局最多成功生成一次，大厅和比赛共用额度；失败不消耗成功次数，普通阶段仍遵循原有请求限流。选择默认不消耗次数，管理员测试不受本局额度限制。重连保留额度，成功开始下一局时重置。
- 关闭玩家预览后，确认提示词生成，无 3D 预览、成功自动装备（仍遵守管理员自定义及换装开关）；客户端依据服务端实际装备状态展示结果。可选择默认。
- 房主开始进入 `preparing`，快照包含 `preparingEndsAt` 和各玩家的 `avatarPreparation`、`avatarGenerated`、`avatarJobId`。已连接玩家全部准备完成后立即开局，否则最多等 100 秒，未完成者取消任务、使用默认后开局。
- 准备阶段允许房间内 8 人各一路生成，绕过普通并发、每小时次数及冷却限制；关闭预览或准备阶段单次生成最多 100 秒。开启预览保持原来大厅预览装备、房主直接开始的流程与普通超时配置。
- 准备中禁止新加入，允许原身份重连。默认选择、准备截止及新局取消旧任务；前端隔离旧轮询响应，避免覆盖新局状态。

## 验证方法

1. `npm test`：执行全部 Node 测试，包括真实本地 HTTP/WebSocket/TLS 链路及执行真实前端脚本的 VM 宿主测试。
2. 对所有修改及新增的 `.js` / `.mjs` 执行 `node --check`。
3. `git diff --check`；检查 `public/index.html`、`server/map.json`、`server/physics.js` 无改动，战斗数值维持原样。
4. 扫描前端直接 `randomUUID()` 调用（排除明确禁止修改的打包 `public/index.html`）。

沙箱内第一次运行网络测试时出现 `listen EPERM 127.0.0.1`，部分进程同时发生 Node 原生 `InternalCallbackScope` 断言异常；已终止该次残留测试进程。随后在沙箱外运行 `npm test`，HTTP/WebSocket 测试可正常执行。运行环境为 macOS、Node.js v24.18.0。

## 覆盖用例

- 无 `randomUUID`、仅有 `getRandomValues` 或完全无 `crypto` 时，后台打开空表单及新增接口不抛异常，编号不重复，且通过真实服务端编号校验（不超过 40 字符）。
- 两种协议保存、测试、启用后，实际玩家请求的 URL、model、Authorization 符合所保存配置；密钥不出现在返回数据中。运行中的任务继续使用提交时接口，另一玩家后续任务使用新接口。
- 第 8 人加入成功、第 9 人被拒；原有战斗、移动、复活、比赛时长和重赛测试回归。
- 失败重试、第二次成功生成被拒、重连保留额度、再来一局重置，以及选择默认和新局后的晚返回隔离。

- 玩家界面 8 人显示、准备名单与倒计时、无预览确认提示词、实际装备状态、断线任务恢复及旧轮次响应隔离。失败任务的重复快照仅触发一次终态读取，新任务仍可重试。
