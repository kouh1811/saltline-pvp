# 分批进入对局验证

验证日期：2026-11-12。分支：`feature/admin-providers-match-prep`。本机 macOS，Node.js v24.18.0。
实现依据：`docs/plans/2026-11-12-staggered-match-entry.md`。

## 行为变化

- 房主开始后统一开启 120 秒选角窗口，适用于预览开／关两种模式。大厅名册随快照更新；未入场玩家自动打开角色工坊，显示倒计时及房内每个人的在线、准备和入场状态。
- 快照新增玩家级 `entered`。首个已装备／默认玩家单独出生，房间进入 `playing` 并启动五分钟计时；后续玩家单独出生和清零自己的战绩，在场玩家不重新出生、不清分、不重置比赛截止时间。删除旧的全员准备完成后统一 `beginPlaying` 流程。
- 准备窗口在 `playing` 期间继续。生成与换装权限依据该玩家是否入场；尚未入场者仍享有准备期生成并发与 IP 预算豁免。已入场者继续遵循原有本局一次生成和对局内换装开关。
- 关闭预览时成功生成自动装备并入场；开启时生成完成仍留在选角，确认装备才入场。连接时不自动装备本地缓存角色，防止绕过确认；已有角色可从最近生成选择后确认装备。
- 到期取消未入场已连接玩家任务，使用默认外观逐个入场。离线者不提前出生，截止后恢复原身份时默认入场。开始后始终拒绝新身份加入。
- 未入场者不渲染为战斗角色，服务端拒绝其开火和换弹，跳过移动与复活，不作为命中目标。入场或窗口结束后自动关闭本次选角，不重复弹出；对局战绩名册标明未入场者。
- 装备的异步资产读取跨过准备截止时间时，先执行默认入场，再重新检查换装权限。生成结果回调也先处理截止，防止晚结果覆盖默认选择。
